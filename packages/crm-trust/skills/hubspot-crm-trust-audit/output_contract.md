# Output Contract

## Final outputs (per run)

```text
crm_trust_report.html        # self-contained visual decision-maker report
crm_trust_report.md          # accessible text-equivalent decision-maker report
operator_appendix.md         # full findings, implementation detail, evidence index
agent_handoff.md             # safety-bounded instructions for a later implementation
findings.json                # machine-readable validated findings
evidence.csv                 # hashed-record evidence rows
report_record_evidence.csv   # local Company/Deal labels mapped to hashes
score.json                   # deterministic CRM Trust score and arithmetic
recommendations.json         # validated action plan and decision ownership
crm_context.yaml             # inferred CRM operating model
schema_discovery_report.md   # schema interpretation + confidence notes
audit_log.json               # run details, no secrets
manifest.json                # snapshot status, counts, and truncation flags
final_gate_report.json       # hashes and deterministic release-gate result
```

## Intermediate artifacts (per run)

```text
processed/*.json                       # sanitized profiles (code)
processed/measurements/<module>.json   # audit measurements (code)
evidence/<module>.csv                  # evidence rows (code, hashed ids)
findings/<module>_findings.json        # judged findings (LLM, validated)
business_context.json, audit_profile.json, crm_context.yaml  # judgments (LLM, validated)
report_narrative.json                   # bounded executive/root-cause narrative (LLM, validated)
harness/run_state.json                  # stage state, attempts, and artifact hashes
harness/tasks/*.json, harness/tasks/*.md # generated BYO Agent task contracts
harness/agent_outputs/reviews/*.json   # isolated reviewer verdicts, round 0 (LLM)
harness/agent_outputs/revisions/*.json # revised copies of findings sent back (LLM, numbers locked)
harness/agent_outputs/rereviews/*.json # single re-review of each revision, approve/reject (LLM)
review_log.json                        # both review rounds (aggregated deterministically)
safety_clearance.json                  # hash-bound phrase clearances
final_gate_report.json                 # deterministic gate result (code)
```

LLM-facing CRM values are labelled as untrusted data. Selected categorical and
property values may be present in processed artifacts when they are needed to
identify the operating model or interpret a finding. Raw snapshots, contact
identity values, note bodies, raw record IDs, portal IDs, and tokens stay
local and are not copied into agent tasks or the record evidence CSV. The
deterministic human-report renderer may include sanitized HubSpot Company and
Deal names and direct HubSpot links as local evidence; these values are never
used as model instructions. Users remain responsible for authorizing their
chosen host LLM to process the bounded CRM context.

Snapshot lifecycle:

- `raw/.checkpoints/*.json` stores a checkpoint after every object page or
  association batch.
- `manifest.json.status` is `in_progress`, `failed`, or `completed`.
- `manifest.json` records `snapshot_started_at`, `snapshot_completed_at`,
  and whether the run was resumed; full-history traversal is best-effort,
  not a point-in-time transaction.
- Only `completed` snapshots may be consumed by downstream phases.
- Resume an interrupted run with
  `python -m scripts.run_crm_trust_audit --resume <run_dir>` using the same
  snapshot window. Raw trees older than the configured retention period are
  pruned, while processed artifacts remain available for local diffing.
- Retention also removes the per-run `raw/run_salt.txt`; after that, old
  evidence hashes cannot be matched back to CRM records. This is intentional
  privacy-preserving behavior and should be considered before follow-up work
  based on an old report.
- Each clearance includes `file_sha256` for the exact deliverable reviewed;
  editing that deliverable invalidates the clearance.
- `final_gate_report.json` records the SHA-256 of every final deliverable and
  of `safety_clearance.json`, so a stored `passed` result can be checked
  against current files.

## Finding schema

See `core/schemas.py::Finding`. Key rules:

- every number traceable to a code-generated artifact
- `severity` assigned by LLM judgment, confirmed by review gates
- `recommendation_type` ∈ safe_operational_actions /
  needs_business_rule_confirmation / do_not_auto_fix
- `auto_fix_allowed` is always `false` in v1

Each item in `recommendations.json` also includes a non-empty
`classification_reason`, `basis`, `evidence_file`, `expected_outcome`, and
`decision_owner`, plus the exact `target`, `current_state`, `desired_state`,
ordered `implementation_steps`, `success_measure`, and `approval_required`.
The recommendation category is contextual and may vary between CRM operating
models. A recommendation without a traceable basis and executable detail is
not complete. `decision_owner` is a recommended accountable role unless an
allowed artifact explicitly identifies a person for the exact decision.
Creating a queue/list is agent-prepared input, not a human action or completed
outcome; completion requires a recorded decision, approved rule, valid
exception, or resolved state.

## Evidence CSV columns

```text
finding_id, object_type, record_id_hash, field_name, issue_type,
current_value_redacted, confidence, recommended_review
```

`record_id_hash = sha256(object_type + record_id + local_run_salt)` — the
salt is generated per run, never global.

## Client report contract

Both decision-maker formats contain: Executive Summary · CRM Snapshot · Data
Quality and Usability · Activity and Data Age · Funnel and Association
Coverage · Key Findings · Root Cause Hypotheses · Recommended Actions · What
This Audit Cannot Determine · Evidence and Supporting Files · Next Review.
Sharing the Report.

The HTML report adds Smartify-styled KPI cards, object-grouped completeness
bars, compact identity-validity checks, record-age distribution, funnel and
association graphics, score arithmetic, priority-grouped findings and actions,
print styles, and the Smartify
website/GitHub footer and a sharing note explaining local HTML and PDF
distribution. The Markdown version preserves the same facts and evidence
links. When available, the title uses the user-supplied business name, known
HubSpot asset names are explicitly type-labelled and bold without making the
surrounding record links or prose bold, and representative Company/Deal names
link directly to their HubSpot records. The local
`report_record_evidence.csv` contains the full hash-to-label mapping but no
portal ID, raw record ID, or URL. Its Company/Deal labels remain identifiable,
so the report package is confidential rather than anonymized.
`operator_appendix.md` contains every validated finding and detailed
implementation instructions. See `reporting_standard.md` for the full format,
visual, language, and evidence-boundary rules.

## BYO Agent execution contract

V1 does not call a model provider and does not require an LLM API key. The
harness generates task packets, waits for Codex/Claude Code (or another host
agent) to write the declared artifact, validates it, and resumes the graph.
Provider-driven execution is an optional future adapter over the same task
packet and artifact contract.
